# 64 · 长期偏好设计（跨会话）

日期：2026-11-22　状态：已落地（待集群恢复后补 128 题复测）

## 决定：只存显式偏好，不存历史结论

用户最终选了推荐方案。做减法的原因不是做不到，是四条风险叠在一起 Risk：

1. 历史答案里的数字会被模型抄进本轮结果——看起来像答对了，其实是旧的；
2. 口径一改（收入低估 5.24 倍那次），旧结论继续影响新答案，错得更隐蔽；
3. 自动归纳把"猜出来的偏好"当事实存下，用户不知道系统记住了什么；
4. 全量历史塞进 prompt 会挤掉语义层与口径陷阱，反而更笨（docs/48 原取舍）。

所以最终只做一件事：**本人明确说出口的口径偏好**（"以后都按播放人数算"），跨会话生效。

## 五道保险

| 保险 | 落地 |
|---|---|
| 显式写入 | `memory.is_remember()` 只认"记住/以后/默认/都按…"句式；普通追问不沉淀 |
| 不存数字 | `extract_preference()` 剥掉结果数字，保留 11-08 这类窗口写法 |
| 口径版本 | 每条带 `caliber_version`，语义层一改就整体不召回 |
| 相关度 Top-K | `_score()` 字符重叠 + 指标命中 + BGE 语义（可选），最多注入 3 条；语义有阈值且需字符信号铺垫 |
| 缓存指纹 | `fingerprint()` 进 `answercache` key，偏好一变旧答案失效 |

## 数据边界

- 表 `user_memory` 独立于 `qa_logs`（不可变证据链）与 `conversations`（可整段删的会话）。
- 按 `user_id` 查询，软删；删除自己的偏好不动审计、不动别人的。
- `eval` / `cli` 不写不读：128 题不会把自身答案沉淀成"用户偏好"。

## 接口

- 问句里说"以后都按 X 算"：短路返回"已记住…"，不再调用图（避免拿偏好指令当业务问题查数）。
- `GET /api/memory`：列自己的偏好；`POST /api/memory`：手工添加；`DELETE /api/memory/{id}`：软删。

## 语义召回（2026-11-23 追加）

用户问"能不能用向量数据库做长期记忆"→ 目标是**召回更准**，不是要新服务。结论：
**向量检索 ≠ 向量数据库**。项目已有 BGE-small ONNX（91MB，512 维）+ onnxruntime，
`memory.recall()` 直接复用 `vecindex.BgeOnnxEncoder` 做单例编码，零新增服务/依赖，
没上 Milvus/Qdrant/pgvector（几十条偏好上 HNSW 索引是负优化，且与磁盘/关服约束冲突）。

三个实测坑，都写在代码注释里：
1. BGE-small 对"人数/次数"一字之差**判反**（"去重用户数"对"按人数算" 0.586 < "按次数算" 0.599）→ 加口径限定词硬规则（+0.8/-0.8），软模型 + 硬规则；
2. 第一轮硬规则两组对立判定互相抵消 → 改成先判口径类别再单向加减；
3. BGE 对完全无关文本也给 0.3~0.4 基础相似度 → `semantic_min=0.55` 阈值，且必须有字符/口径信号铺垫才加语义分，否则"今天天气"也会召回偏好。

配置：`memory.semantic: true`（关掉退回纯字符方案，0 模型加载）、`memory.semantic_min: 0.55`。
自测 `selftest_memory.py` 34/0（含同义改写、人数/次数对立、地域、无关问句、单例复用）。

## 已知边界

- 偏好文本是规则剥出来的，复杂句式（"上次那个口径以后都按那个来"）剥不出就写不进去——宁可少记不猜。
- `MemorySaver` 的 HITL 现场仍是进程内，多 worker 要换 Redis/PG checkpointer（与 docs/63 同源）。
